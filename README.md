# OFFICE CHAOS

A top-down action RPG dungeon crawler. It's a medieval loot game trapped inside a surreal corporate office simulation.
Built with **Godot 4.7** + **Blender 4.5** (driven headless from the terminal) using the **Compatibility (OpenGL)** renderer. This Mac's Intel Iris GPU crashes under Forward+/Vulkan, so the project stays on Compatibility. The game uses no external assets: every mesh, sound and UI element is generated from code and editable JSON.

## Art style

**Direction:** late-90s digital-world anime (Digimon Adventure season 1) meets the office: cel shading with bold outlines and flat two-tone shadows, vivid primaries against deep indigo and purple voids, cyan / neon-green data effects, soft film grain and a gentle CRT scanline. No gloss, no heavy bloom.

- **The world beyond the walls** (`scripts/world/backdrop.gd`): every level floats over a machine wilderness: a data-stream ocean with a wireframe grid (`shaders/data_ocean.gdshader`), floating islands with circuit-vein forests, pixel deserts, giant file folders, clock towers, server monoliths and glowing data-gates, plus binary drifting up from the void. Islands fade into the void with depth. Tune per level with `"backdrop": {"biomes": [...], "islands": N, "ocean_deep": ..., "void": ...}` or switch it off with `"no_backdrop": true`.
- **Digitizing:** defeated enemies dissolve into rising 0s and 1s with sweeping scan rings and pixel fragments; hits throw chunky pixel bursts and a cyan scan-line flash.
- **Tier glow:** Stock none, Patched soft green, Overclocked orange, Root cyan circuit veins with a glitch flicker (the reserved colour `#3ff1fe` flickers in `toon.gdshader`) and unstable glitch edges. Inventory icons carry the same glow.
- **HUD:** a 90s handheld: beige plastic bezels, green LCD gauges with segments and monospace labels. Menus keep the Teams-style office look.

The look is a flat, illustrated toon style:
- `shaders/toon.gdshader` gives one hard light/shadow step. The shadow colour comes from each level's ambient tint.
- `shaders/outline.gdshader` draws inverted-hull ink lines.
- Each level has its own pastel palette, set in `levels/*.json` under `theme` and `theme.props`.

Every part is built from a **Blender mesh kit** (`assets/meshes/kit.glb`): rounded boxes, soft boxes, cylinders, cones, spheres, gems and rings with smooth normals. The kit is generated by a script, so no Blender MCP is needed. Rebuild it after editing the bevels:

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_mesh_kit.py
```

Enemy, item and prop parts in JSON use these kit shape names (`box`, `softbox`, `cyl`, `cone`, `sphere`, `gem`, `torus`, plus the character shapes `head`, `dome`, `capsule` and `blazer`, and the office dressing shapes `pot`, `mug`, `jug` and `leaf`).

### Level dressing

- **Wall props:** levels place tall props along their walls when they are built: floor plants (`L`), bookshelves (`S`), vending machines (`V`) and floor lamps (`J`). Only rooms at least 4 cells deep get them, never beside doors, glass or stations, so paths stay open. Tune them per level with `"dressing"` (weights per prop letter) and `"dressing_density"`.
- **Coworkers:** `"coworkers": N` adds N office workers who wander the level.
- **Rug and motes:** a theme can add a round rug at the player start (`theme.rug`) and floating dust (`theme.motes`, `motes_color`, `motes_rise`).
- **Cables:** in corrupted zones the floor shader draws two layers of continuous cables with travelling data pulses, and `c` cells hold curved cable bundles around a power strip.

Photograph every level from the game camera into `user://tour/`, which is handy for before/after art comparisons (run it windowed):

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --tour
```

### Characters

The employees (you, the Lobby staff and every preview) follow the Animal Crossing / Pocket Camp look, in office suits:
- **Proportions:** a big round head, a short A-line blazer, stubby legs, round mitten hands and chunky shoes.
- **Painted details:** `shaders/character.gdshader` paints the details onto the meshes the way Animal Crossing paints textures:
  - **Face:** eyes with highlights, lashes, brows, blush, nose, mouth and glasses.
  - **Suit front:** shirt, tie, lapels, buttons, pocket square and a clip-on ID badge.
  - Everything stays crisp at any zoom and costs no textures.
- **Expressions:** the face blinks and reacts:
  - **Hurt** (`> <`) when hit.
  - **Happy** (`^ ^`) on promotion, rare loot and unlocks.
  - **Knocked out** (`x x`) on death.
  - Desk staff smile when you talk to them.
- **Portraits:** the HUD's messenger avatar and the save-slot list show a rendered portrait of your character. The HUD portrait mirrors your expressions.
- **Readability:** heads tilt up slightly and faces get extra light, so they read from the high game camera.
- **Shared lighting:** both shaders share their lighting through `shaders/toon_light.gdshaderinc`.

Render every hairstyle, face, expression and body, plus the Lobby desks, as reference sheets in `user://char_sheet/` (run it windowed, from the project folder):

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --chars
```

## Launch

You need **Godot 4.7**; the standard build is enough because the project is pure GDScript. Run the terminal commands from the project folder. They use the macOS app path: on Windows or Linux, replace `/Applications/Godot.app/Contents/MacOS/Godot` with your Godot executable.

1. Get the project:
   ```bash
   git clone https://github.com/rodrigopcoelho/OfficeChaos.git && cd OfficeChaos
   ```
2. Open Godot 4.7 → **Import** → select `OfficeChaos/project.godot` → **Run** (F5).
3. Or from a terminal, import the assets once (the editor does this for you when you open the project), then run the game:
   ```bash
   /Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
   ```
   ```bash
   /Applications/Godot.app/Contents/MacOS/Godot --path .
   ```
4. To run the automated play-through test (108 PASS/FAIL checks covering every system, including simulated controller input), use:
   ```bash
   /Applications/Godot.app/Contents/MacOS/Godot --headless --path . -- --qa
   ```
   Add `--shots` (without `--headless`) to save screenshots to `user://qa_shots`.
5. To run the performance benchmark (frame times, draw calls, level build times, combat and boss stress scenes, and a level-cycling memory-leak check), run it windowed:
   ```bash
   /Applications/Godot.app/Contents/MacOS/Godot --path . -- --bench
   ```
   `--bench --quick` measures two scenes. Experiment flags such as `--quality=low`, `--shadow=off`, `--nooutline` or `--noactors` show what each feature costs. `--quality=` only applies to that run: your saved graphics setting is put back afterwards.

## Controls (both rebindable in Settings)

The controller layout follows **Minecraft Dungeons II**. The game switches automatically to whichever device you touch last: button prompts update and the mouse cursor hides while you use a controller.

| Action | Keyboard & mouse | Controller (Xbox names) |
|---|---|---|
| Move | WASD / arrows | Left stick |
| Aim | Mouse | Movement direction, with **aim assist** toward the nearest virus ahead |
| Attack (hold) | Left mouse | X |
| Dodge roll (invulnerable) | Right mouse | LB, or **flick the right stick** in any direction |
| Jump (attack mid-air for a **Slam Impact**) | Space | A |
| Weapon special ability | Q | Y |
| Interact | E | B |
| Inventory / equipment | I | D-pad Up |
| Network map | M | View |
| Pause | Esc | Menu |

**Menus with a controller:**
- The D-pad or left stick moves the focus ring.
- A confirms and B goes back or closes.
- LB/RB switch the tabs of the CubeLink app.

**Optional controller settings:** vibration and aim assist can be turned off under *Settings → Feedback*.

## Performance settings

*Settings → Graphics & performance:*
- **Graphics quality:**
  - **High** (default) is the full look.
  - **Medium** uses lighter 2-split shadows.
  - **Low** has no shadows, glow or MSAA. It's the best choice for older Macs.
- **Frame-rate cap:** Off / 30 / 60 / 120. On slower machines a **30 FPS cap gives perfectly even frame pacing**.
- **VSync:** on or off.

Measured on the Intel Iris Plus MacBook (Compatibility renderer, uncapped, worst-case scenes):

| Scene | Before optimisation | High | Low |
|---|---|---|---|
| Lobby | 24 FPS | 47 FPS | 60 FPS |
| Floor 7, busiest spot (27 viruses) | 19 FPS | 30 FPS | 51 FPS |
| Combat crowd, worst frame | 393 ms freeze | 83 ms | – |

**How it's fast:**
- **Static batching** (`scripts/systems/mesh_batcher.gd`): every static prop is merged into one mesh per 8 m chunk. Colour, glow and ink-line width live in vertex attributes, which cut draw calls about 4×.
- **Merged characters:** each character limb is one mesh.
- **Pooled effects** (`scripts/world/fx_pool.gd`): sparks, damage numbers, rings, slashes and lightning are recycled instead of created and freed.
- **Shader warm-up:** behind the loading fade, each level shows itself and one of every effect from above, so shaders compile there and not mid-fight.
- **Tighter shadows:** a 30 m shadow distance, which covers everything the camera can see.
- **Bounded caches:** no more per-size mesh leaks. The leak check holds object counts flat across level loads.

## The loop

1. Create a character on the onboarding form: name, body type, badge-photo face, hairstyle, palette and save slot.
2. Start in **The Lobby**. Its three staffed desks are Procurement (shop), the IT Hardware Forge (blacksmith) and Software Licensing (**Upgrades**).
3. Take the elevator to **Floor 7**. Fight corrupted processes, absorb DATA, collect Gold and loot equipment drops. Purple-crowned **corrupted** viruses are tougher and drop **Corrupted Gold**. Walking up to a golden terminal unlocks it.
4. Find the **red meeting room door**. It is a random one of four candidates each visit. Accept the invite to enter **Server Room B**.
5. Fight through the dungeon and an elite room to **THE REGIONAL MANAGER**, a two-phase boss with telegraphed slams, memo barrages, charges, spirals, corrupted floor zones and summons.
6. Claim the Performance Bonus chests and leave through the Emergency Exit. Each boss kill raises your **Security Clearance**, which makes enemies stronger and rewards bigger.
7. Dying sends you back to the Lobby with everything you own intact.

## Adding / editing content

**Add a sword.** Copy an entry in `data/items/weapons.json`, then give it a new unique `id` and change `name`, `damage`, `attack_speed`, `range`, `arc`, `rarity` and so on. `visual.parts` is a list of boxes, spheres, cylinders and cones. The grip is at the origin and the blade points along **-Z**. To sell it, add the id to `shop.json`'s `pool`. Droppable items automatically join loot tables by rarity.

**Change weapon damage.** Edit `damage` in its JSON entry.

**Add an enchantment.** Add an entry to `enchantments.json`. Pick a `hook` (`pre_hit`, `post_hit`, `on_crit`, `on_kill`, `on_swing` or `passive`) and an existing `effect`:
`heal_on_hit, dot_on_hit, buff_on_crit, chain_on_hit, shield_periodic, bonus_vs_low_hp, teleport_on_hit, stun_on_hit, explode_on_kill, heal_on_kill, gold_on_kill, wave_on_swing, stat_bonus`.
Give it three `levels` of parameters. Descriptions use `{key}` and `{key%}` placeholders. That's all a reused effect needs, with no code. A brand-new behaviour needs one extra `match` branch in `scripts/systems/enchants.gd`.

**Add an enemy.** Add an entry to `enemies.json` and set:
- `move`: `chase`, `erratic` or `kite`
- `attack.type`: `melee`, `slam`, `lunge` or `projectile`
- optional `aura`, `summon` and `blink` behaviours
- `data`, `gold`, `loot_table` and `visual.parts`

Animated limbs use the groups `leg_l`, `leg_r`, `arm_l`, `arm_r` and `head`. Then reference the enemy in a level's `encounters`.

**Add a new kind of level prop (code).** Build it inside `GameWorld` with `MeshFactory.box/shape` under `static_root` (it is merged into the chunk batches automatically). Anything that animates, flickers or changes colour must go under `level_root` instead (or use a `unique` material). Interactables keep their own nodes and merge their static parts with `MeshBatcher.merge_children()`.

**Add a hairstyle, face, body or palette.** Everything is in `data/appearance.json`, and the onboarding form picks new entries up automatically:
- **Hairstyles** are lists of kit parts in *head units*: the head is a 1×1×1 box around its centre, and -z is the face.
  - Colours can be palette tokens (`hair`, `accent`, `skin`).
  - The usual base is a `dome` cap on top plus a `dome` rotated `[90, 0, 0]` over the back of the head.
  - Set `hide_ears` for hoods and long hair.
- **Faces** are numbers for the face painter, measured in head widths from the head's centre:
  - Eyes: `eye_pos`, `eye_size`, `sclera` with `iris_color`, `shine`, `lid` (sleepy), `lash`, `flick`.
  - Brows: `brow`, `brow_tilt`.
  - Mouth: `mouth` (`smile`, `cat`, `open`, `flat`, `grin`).
  - Extras: `glasses` (`round`, `square`), `blush`, `freckles`, `bags`.
- Run `-- --chars` to see the result.

**Change drop rates.** Edit `loot_tables.json`. Every source (enemy tiers, chests, the boss) has rarity percentages for the early / mid / late game (picked from your gear Power); each block must add up to 100.

### Items, rarities and icons

- **Rarities** (`progression.json` → `rarities`): **Stock** (common, 100 % stats, 0 passives), **Patched** (rare, 110 %, 1), **Overclocked** (special, 120 %, 2) and **Root** (unique, 130 %, 2 passives + a unique effect). Add a rarity there and in the loot tables; nothing else is hard-coded.
- **Basic items** have `"tiers": true` and expand into Stock / Patched / Overclocked variants (`<id>`, `<id>_patched`, `<id>_overclocked`). Patched and Overclocked models get tape / patches and glowing trim automatically on every part marked with a `"role"`.
- **Root items** are fused uniques with their own models. `"base"` names the basic item they're built on (they inherit its stats) and armor Root pieces carry a `"set"`: Cablemail, Mainframe Plate, Kernel Panic, Floppy Scale, Liquid-Cooled.
- **Item fields:** `id`, `name`, `slot` (type), `rarity`, base stats, `min_level`, `drop_sources` (enemy / chest / boss), `effects` (unique effects), `visual` (the 3D model). Passive ability ids are rolled per drop from `passives.json`.
- **Loot bonuses:** passives like Lucky (+% Patched or better), Root Access (+% Root) and Scavenger (+% drop rate) shift the odds, capped by `progression.loot_modifiers`.
- **2D icon art:** each item's inventory icon is baked from its 3D model into `assets/icons/<id>.png` (ink outline + drop shadow). Re-bake after changing a model, then re-import (both windowed / headless respectively):

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --icons
```

  A contact sheet of every icon is saved to `user://icon_sheet.png`.

**Tune progression.** In `progression.json`: `power` (how much each Power point adds to gear and to enemies, and the drop spread), `corrupted` (spawn chance and stat multipliers of corrupted enemies, Corrupted Gold drops) and `enchanting.corrupted_gold_cost` (what levelling an Upgrade costs).

**Edit or add a level or dungeon.**
1. Copy `data/levels/dungeon_server_room.json`, change the `id` and edit the `map` rows.
2. Map legend:

   | Character | Meaning |
   |---|---|
   | `#` | wall |
   | `.` `,` | floor |
   | `g` | glass |
   | `d` | desk |
   | `k` | cubicle partition |
   | `t` | table |
   | `x` | server rack |
   | `p` | printer |
   | `w` | water cooler |
   | `f` | filing cabinet |
   | `c` | cables |
   | `o` | chair |
   | `P` | spawn |
   | `G` | golden computer, matched in reading order to `computers` |
   | `E` | elevator, matched in reading order to `exits` |
   | `R` | red-door candidate |
   | `X` | exit |
   | `C` | reward chest |
   | `K` | boss |
   | `$` `B` `N` | stations |
   | `1`–`9` | encounter markers, defined in `encounters` |

3. Add the file to `manifest.json`.
4. Add an entry in `dungeons.json` pointing to the new level, and list that entry in some level's `dungeon_doors.dungeons`.

## Implemented features

- Main menu over a live 3D lobby, character creation with a 3D preview, and 3 save slots with load/delete.
- Animal Crossing–style chibi employees in office suits:
  - Creation options: 5 body types, 9 painted faces, 11 hairstyles (including a beret and a work-from-home hood) and 8 palettes.
  - Blinking and reaction expressions.
  - Portrait avatars in the HUD and on save slots.
- Twin-stick combat: hit arcs, crits, knockback, hit-stop, screen shake, i-frame dodge roll, jumping with a Slam Impact (bonus damage to the enemy you land on plus a knock-back shockwave), and 5 special abilities.
- 5 virus enemy types (TROJAN.EXE, WORM.BAT, RANSOM.LOCK, SPYWARE.DLL, ROOTKIT.ADMIN) with real AI: detection, A* pathfinding, line of sight, telegraphed attacks, an aura buffer/summoner, a draining kiter and a blinking crawler.
- A two-phase boss with 6 attack patterns, telegraphs, a phase transition and a death sequence.
- Minecraft Dungeons–style progression: gear Power drives your strength, enemies scale to it, DATA levels grant Upgrade Points only. Gold and Corrupted Gold currencies, rarity-beamed loot (Common / Special / Unique).
- 124 item variants: 17 basic weapons (swords, axes, blunt, whips, polearms, dagger, scythe) and 12 basic armor pieces in Stock / Patched / Overclocked, plus 17 Root weapons and 20 Root armor pieces in five themed sets, each with its own 3D model and baked 2D icon. Rarity-scaled stats, rolled passive abilities, Power and compare tooltips.
- A modular Upgrades system (16 effects, levels I–III, paid with Upgrade Points and Corrupted Gold), blacksmith reforging (+5), and a shop with restock and selling.
- Golden-terminal teleport network map, randomized red dungeon doors, and corruption that grows with distance.
- A CubeLink corporate-messenger UI styled after Microsoft Teams: slate app rail, purple title bar, persona card with presence, Teams-style desktop notifications and calendar-invite dialogs.
- Death without loss and respawn in the hub; autosave plus manual save; rebindable keyboard/mouse **and controller** bindings; audio, graphics-quality, frame-cap and VSync settings.
- Full controller support (Minecraft Dungeons II layout) with aim assist, flick-dodge, vibration, focus-ring menu navigation and LB/RB tab switching.
- Procedural audio, toon shading with ink outlines, flickering fluorescents and a CRT post-process.

## Fixes in the polish pass

- The character preview was blank on the Profile tab and when the onboarding form first opened.
- The HUD leaked icon callbacks when item icons could not render, and rebuilt its avatar for every DATA orb picked up.
- Mesh caches were keyed by random sizes (lightning arcs, glitch fragments), so memory grew with every level load.
- Enemy knockback leaked into steering after wall collisions.
- Viruses could not path to a player standing beside a desk.
- Hazards played their opening burst at the world origin.
- Summoned viruses outside the boss room appeared without their spawn effect.
- The interaction prompt cleared at the wrong moment.
- The single floor mesh only received 8 of the level's lights, so most light pools were missing.

## Known limitations

- **No standalone build yet.** Godot export templates are not installed on this machine. To build one, install them in Godot under *Editor → Manage Export Templates*, then use *Project → Export → macOS*.
- There is one hub, one exploration floor and one dungeon. Repeat runs get harder through Security Clearance tiers rather than new maps.
- Models are assembled from the rounded Blender kit shapes. There are no hand-sculpted meshes or skeletal rigs; animation is procedural.
- Combat and boss balance was tuned through automated runs. Expect some numbers to need tweaking after real play.
- Big fights with 20+ viruses on screen still dip to ~30 FPS on High on an Intel Iris Mac. Use Low or the 30 FPS cap there.
- Controller layout follows community-documented Minecraft Dungeons II defaults (no official Mojang keybind table was available). Every binding can be changed in Settings.
- Physics interpolation is not enabled, so below 60 FPS movement can look slightly uneven. The 30 FPS cap avoids this.
